Architecture overview

Scanlytic Forensic AI follows a pipeline architecture, enabling deterministic, auditable analysis stages while keeping each component independent and testable.

Core pipeline stages

Intake and validation, classification, feature extraction, scoring, and reporting are executed in sequence to preserve analysis integrity.

Separation of concerns

CLI orchestration, analysis logic, feature extraction, scoring, reporting, and persistence are modular to simplify extension and testing.

Component map

Key modules and their responsibilities.

cli.py

Argument parsing, validation, and orchestration entry point.

core/analyzer.py

Coordinates classifier, extractor, and scoring stages.

features/

Extracts hashes, entropy, headers, strings, and metadata.

reporting/

Generates JSON, CSV, and HTML outputs for audit trails.

Design priorities

The pipeline design promotes predictable behavior, easy testing, and integration into security operations tooling.

Deterministic outputs

Repeatable analysis for court-ready evidence and audits.

Extendable stages

Add new extractors or scorers without rewriting the pipeline.

Defensible processing

Local-first design avoids data leakage and keeps evidence intact.
